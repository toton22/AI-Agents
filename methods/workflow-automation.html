Agents inside workflow tools

Build the Meridian Deal Desk agent in n8n, node by node, with a Google Sheets lookup, a Code tool for margin and a Slack approval gate, and compare n8n with Zapier, Make and Power Automate for your own team.

Workflow automation tools started life connecting apps: "when a form is submitted, add a row to a sheet and post in Slack". Around 2024–25 they all added an AI agent step. Now a workflow can hand a messy request to a model, let it pick tools, and carry on with the rest of the process afterwards. You still see every step on a canvas. That visibility is the main reason managers like this method.

Four tools come up in most Indian and global companies:

  • n8n: open, self-hostable, with an AI Agent node that connects to chat models, memory and tools as sub-nodes. Popular with technical teams who want their data on their own servers.
  • Zapier: the largest app catalogue, with Zapier Agents (built with Zapier Copilot) and AI steps inside Zaps.
  • Make: a visual scenario builder with Make AI Agents, which run on the same canvas and show each decision in a Reasoning panel.
  • Power Automate: Microsoft's workflow tool, with AI Builder prompts and document processing, the long-standing Approvals connector, desktop flows for RPA, and close ties to Copilot Studio.

What changed recently (as of October 2026)

n8n has moved to its 2.x line. Every AI Agent node now works as a Tools Agent (the old agent-type setting is deprecated), and n8n added human review for tool calls: you can gate any tool so the workflow pauses and asks a person in Chat, Slack, Teams, Gmail, Outlook, Telegram, Discord, WhatsApp or Google Chat before it runs. n8n also has a separate Agents feature in preview, with a builder, skills, knowledge, schedules and channels; self-hosted support starts at version 2.32.3. Make announced its "next generation" of AI Agents in February 2026, available on all plans. Zapier continues to push Agents alongside Zaps.

Manager's lens

Workflow tools are where agents meet operations. The agent is one box on a canvas; the boxes around it decide what triggers it, what it may touch and who signs off. If your process owner can read that canvas and point at the approval step, you've built something an auditor can follow. That's worth more than a clever prompt.

When to pick it

Pick a workflow tool when the agent is part of a process: something triggers it (a chat, an email, a new row, a schedule), it needs data from several systems, and the result must flow somewhere (a CRM update, a Slack message, an approval). The Deal Desk is a good fit. So is invoice triage, lead routing, or summarising daily tickets for a team lead.

Among the four, the choice usually comes down to where your systems are and who maintains the thing. Microsoft shop: Power Automate. A non-technical team that needs a niche SaaS app connected tomorrow: Zapier. Complex branching on a budget: Make. Data must stay on your servers, or you want to inspect and version everything: n8n.

Don't pick it when you need fine-grained control over the reasoning loop (multiple cooperating agents, custom memory, evaluation suites in code); move to LangGraph or the OpenAI Agents SDK. And don't pick it for a pure document Q&A bot. A no-code assistant does that with far less effort.

Strengths

  • Agents run on real triggers, not only when someone chats.
  • Deterministic steps (lookups, maths, routing) sit next to the LLM step.
  • Built-in human approval steps in every tool.
  • Every run is logged with inputs and outputs, step by step.
  • n8n can be self-hosted, which helps with data residency and DPDP comfort.

Watch-outs

  • Canvases grow messy fast; you need naming and documentation discipline.
  • Model costs sit on top of platform costs and are easy to forget.
  • Credentials for many systems live in one tool, so it becomes a security target.
  • Self-hosting n8n means you own patching, backups and uptime.
  • Agent features change monthly; tutorials from 2025 are often out of date.

How it works

In n8n, an agent workflow has a trigger node (for chat: the Chat Trigger, "When chat message received") feeding an AI Agent node. The agent node has sockets underneath for sub-nodes: one Chat Model (OpenAI, Anthropic, Gemini, a local model and so on), an optional Memory (so it remembers earlier turns in the conversation), and one or more Tools. A tool can be almost any n8n app node used in tool mode (Google Sheets, HTTP Request, Postgres), a Code tool, or a whole sub-workflow. n8n's documentation says you must connect at least one tool.

When a message arrives, the agent node sends the model your system message, the conversation so far and the list of tools with their descriptions. The model replies either with an answer or with a tool call; n8n runs the tool and sends the result back; the loop repeats until the model answers. This is the same loop as in M04, drawn as boxes.

Two n8n features matter for business use. First, $fromAI(): inside a tool node's parameters you can mark a field as "let the model fill this", with a name and description, so the Google Sheets lookup gets the customer name the model extracted. Second, human review: configured from the agent's Tools panel, it sits between the agent and the tools you choose. On approve, n8n's docs say "the tool executes with the input specified by the AI"; on deny, the action is cancelled and the model is told it was rejected.

Build the Deal Desk agent

You need n8n (n8n Cloud trial, or self-hosted with Docker), a Google account for Sheets, a Slack workspace for approvals, and an API key for a chat model. Store every key in n8n's Credentials, never in a node's text field.

  1. Create the customer sheet

    In Google Sheets, make a sheet Customers with headers id, name, tier, revenue_lakh, late_payments, margin_pct and the five Meridian rows. Add a second tab Decisions with headers timestamp, customer_id, discount_pct, decision, approver, outcome. That second tab is your audit log.

  2. Add the Chat Trigger

    New workflow → add Chat Trigger ("When chat message received"). For testing, the built-in chat panel is enough. Later you can make the chat public behind authentication, or swap the trigger for Slack or Teams.

  3. Add the AI Agent node and its system message

    Connect an AI Agent node to the trigger. In its options, set the system message:

    You are the Meridian Deal Desk agent. For every discount request:
1. Use find_customer to get the customer's row. Ask if the name is unclear.
2. Cap = 3% if late_payments >= 2, else Bronze 5%, Silver 8%, Gold 12%.
3. Use margin_after_discount to compute margin after the discount.
4. APPROVE only if discount <= cap AND margin after >= 12.
   Otherwise call request_approval with approver "Sales Manager",
   or "Regional Head" if the discount is above 15%.
5. If request_approval is denied, say so and suggest the highest
   discount that is within policy. Never promise an unapproved discount.
Reply with: Decision, Checks (cap, margin after), Next step.

    What this does: same policy as every other page on this site, written as an ordered checklist the model follows. Point 5 follows n8n's own advice to tell the agent which tools need approval and what to do on a denial.

  4. Connect a chat model and memory

    Under the agent, add a Chat Model sub-node (for example OpenAI Chat Model or Anthropic Chat Model) with your credential. Add Simple Memory so a follow-up like "and if they take 8% instead?" still knows which customer you mean.

  5. Tool 1: find_customer (Google Sheets)

    Add a Google Sheets tool. Name it find_customer, description: "Look up a Meridian customer by name. Returns id, tier, late_payments and margin_pct." Operation: get rows, sheet Customers, filter column name, and set the filter value with the "let the model define this" option (it inserts a $fromAI() expression) described as "The customer's name as written in the sheet".

  6. Tool 2: margin_after_discount (Code tool)

    Add a Code tool named margin_after_discount, description: "Computes gross margin after a discount. Input: JSON with current_margin_pct and discount_pct." Language JavaScript:

    // 'query' holds what the agent sent to this tool
const input = typeof query === 'string' ? JSON.parse(query) : query;
const current = Number(input.current_margin_pct);
const discount = Number(input.discount_pct);
if (Number.isNaN(current) || Number.isNaN(discount)) {
  return 'Error: send numbers for current_margin_pct and discount_pct';
}
const after = current - discount;           // simplified policy formula
return JSON.stringify({ margin_after_pct: after, meets_floor: after >= 12 });

    What this does, line by line: it reads the agent's input (handling it whether it arrives as text or as an object), turns both values into numbers, returns a clear error if they aren't numbers, subtracts the discount from current margin, and sends back the result plus a yes/no on the 12% floor. The model never does the arithmetic itself; it only reads the answer.

  7. Tool 3: request_approval, behind human review

    Open the agent's Tools panel, find Human review, and choose Slack as the approval channel (Gmail or Microsoft Teams work the same way). Connect a tool to the review step: a Google Sheets append-row tool named request_approval that writes customer_id, discount_pct, approver and reason into Decisions, each filled by $fromAI(). In the review message, show the tool name and its parameters so the approver sees exactly what the agent wants to do, for example the text {{ $tool.name }} followed by {{ JSON.stringify($tool.parameters) }}.

    What this does: when the agent decides to escalate, the workflow pauses and posts the request to the Sales Manager in Slack with approve and deny buttons. Approve: the row is written and the agent tells the salesperson. Deny: nothing is written, and the agent is told it was rejected.

  8. Test the three cases, then activate

    Run Sahyadri 10%, Bluewave 6% and Kite 5% in the chat panel. Open each execution and check the agent's tool calls. When all three behave, activate the workflow.

About exporting the workflow as JSON

n8n workflows export as JSON and can be imported elsewhere, which is how teams version them in Git. We haven't printed one here because node type names and parameter shapes change between n8n versions; export your own working version from the menu and commit that file.

Sahyadri Hospitals wants 10% off their next order. Can we do it?
find_customer(name="Sahyadri Hospitals")
{"id":"C-101","name":"Sahyadri Hospitals","tier":"Gold","late_payments":0,"margin_pct":22}
Gold, no late payments, so cap is 12%. 10% is within the cap. Check the margin.
margin_after_discount({"current_margin_pct":22,"discount_pct":10})
{"margin_after_pct":12,"meets_floor":true}
Exactly at the 12% floor, which is allowed. Approve; no approval tool needed.
Decision: APPROVE. Checks: Gold cap 12%, margin after 12% (floor 12%). Next step: draft reply to Sahyadri confirming 10% on the next order. Note this uses all the margin headroom; there's no room for extra freight concessions.
Tip

Write each decision to the Decisions tab, approved or not, with a normal (non-AI) Google Sheets node after the agent. Then a pivot table tells the sales head every Monday how many discounts went through, at what average, and how many needed approval.

Taking it to production

Hosting choice

n8n Cloud is managed by n8n. Self-hosted n8n (Docker on your own server or a cloud VM in an Indian region) keeps workflow data and credentials inside your perimeter, which helps when legal asks where customer data goes under the DPDP Act. The trade-off is that you now run a production service: updates, backups of the database that stores workflows and credentials, monitoring, and uptime. n8n is released under its Sustainable Use License, and some features (for example, certain enterprise controls) need paid editions, so check the edition comparison before committing. Zapier and Make are cloud-only. Power Automate runs in Microsoft's cloud, with desktop flows on your machines.

Identity and access

Turn on SSO for the tool's editor accounts, and separate who can edit workflows from who can use them. Use service accounts for Google Sheets and Slack credentials, not someone's personal login; when that person leaves, the workflow should keep running. Give the Sheets credential access to the two tabs it needs and nothing else.

Cost control

You pay twice: the platform (executions, tasks or credits, depending on the vendor) and the model provider (tokens). An agent that loops through five tool calls costs five times what a single call does. Set a sensible maximum number of iterations on the agent, choose a smaller model for lookups, and put a spending limit on the model API key.

Monitoring and approvals

Every execution is logged, which is excellent for debugging and a privacy question at the same time: logs contain customer names and margins. Set a retention period. Add an error workflow that alerts someone when the agent fails. For approvals, the Slack message is the request, but the Decisions tab is the record. Review approval patterns monthly with the sales head.

  • Hosting decided (cloud or self-hosted) with a named owner for updates and backups
  • Credentials held in the tool's credential store, under service accounts
  • Editor SSO on; production workflows editable by two people only
  • Max iterations set on the agent; API spending limit set
  • Execution log retention set; error workflow alerts a person
  • Decisions logged to a sheet or database for audit
Watch out

A workflow tool with credentials to Gmail, Sheets, Slack and your CRM is a prize for attackers. If a prompt injection in an incoming email convinces the agent to call the wrong tool, the damage is limited only by what those credentials can do. Gate every write action with human review until you have months of clean logs. M11 covers this in depth.

Case · Finance

Invoice triage at a mid-sized logistics company

A typical pattern: an accounts payable team receives a few hundred vendor emails a day. A workflow agent reads each one, extracts invoice number, amount and GSTIN, and matches against open purchase orders in the ERP. Clean matches are queued for posting; mismatches go to a person with the agent's notes. The quiet benefit is the log. For the first time, the team can see which vendors send the messiest invoices, and that becomes a conversation with procurement.

Practice and quiz

  1. Swap the trigger

    Replace the Chat Trigger with a schedule that reads new rows from a "Requests" tab every hour and runs the agent on each. What else must change?

    Hint / model answer

    The agent's input now comes from a row, so the prompt source changes from the chat to a field (for example "Customer: {name}, discount: {pct}"). There's no chat to reply to, so the output must be written back to the row or sent to the salesperson. Memory isn't useful across unrelated rows; remove it. Human review still gates request_approval.

  2. Price a month

    Assume 40 salespeople, 3 discount requests each per working day, 22 working days, and an average of 3 model calls per request. How many model calls a month? What would you check on your platform's pricing page?

    Hint / model answer

    40 × 3 × 22 = 2,640 requests; × 3 = 7,920 model calls a month. Check how the platform counts usage (per execution, per task, per step), whether AI steps cost extra, and the model's per-token price for your average prompt length. Then add a 30% buffer for retries and follow-ups.

  3. Pick the tool

    Meridian's IT runs Microsoft 365 but the sales team uses Google Sheets for pricing. Legal wants customer data kept in India. Recommend one of the four tools in five sentences.

    Hint / model answer

    A defensible answer is self-hosted n8n in an Indian cloud region: data stays in your environment, it has both Google Sheets and Microsoft connectors, and human review gates the approval. Power Automate is also defensible if IT will move the pricing sheet to SharePoint, since governance is already in place. State the trade-off: n8n needs someone to run it.

In n8n, what must an AI Agent node have connected at minimum, according to the docs?

  1. A memory sub-node
  2. An output parser
  3. At least one tool (plus a chat model)
  4. A Slack credential

n8n states you must connect at least one tool, and a chat model is what the agent reasons with. Memory and parsers are optional.

What happens when a human reviewer denies a gated tool call in n8n?

  1. The tool doesn't run and the model is told it was rejected
  2. The workflow crashes
  3. The tool runs with default values
  4. The tool runs but the result is hidden

Deny cancels the action and informs the AI, which is why the system message should say what to do on a denial.

Why compute margin in a Code tool instead of letting the model subtract?

  1. Models can't read numbers
  2. The Code tool is free while models cost money
  3. n8n doesn't allow arithmetic in prompts
  4. Code gives the same exact answer every time and can be tested

Models usually get 22 − 10 right, but "usually" isn't a control. Code is exact, repeatable and testable.

Which tool is the only one of the four that you can self-host entirely?

  1. Zapier
  2. n8n
  3. Make
  4. Power Automate

n8n can run on your own servers. Power Automate has desktop flows on your machines, but the service itself runs in Microsoft's cloud.

The biggest security risk specific to workflow-tool agents is:

  1. The canvas being visible to colleagues
  2. Using spreadsheets as a data source
  3. Many system credentials in one place, reachable by an agent that reads untrusted input
  4. Running workflows on a schedule

An injected instruction in an email can steer an agent to misuse whatever credentials the workflow holds. Least-privilege credentials and human review on writes are the defences.

Key takeaways

  • Workflow tools put the agent inside a process: triggers before it, systems and approvals after it.
  • In n8n, the agent node plus sub-nodes (model, memory, tools) is the whole architecture; human review gates the risky tools.
  • Keep arithmetic in code and decisions in a log you can audit.
  • Choose among n8n, Zapier, Make and Power Automate by where your systems live and who will maintain the workflow.
