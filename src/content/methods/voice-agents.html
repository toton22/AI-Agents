A voice agent is the same agent you've built on other pages (instructions, tools, a model that decides) with ears and a mouth attached. A salesperson on a customer site in Nashik calls a number, says "Can I give Sahyadri ten percent?", and hears an answer in a couple of seconds. No app, no typing, no login screen in the car park.

That's the appeal. The hard part is everything humans do without noticing in a phone call: knowing when the other person has finished speaking, coping with interruptions, filling silence while you look something up, and understanding Marathi-accented English mixed with Hindi on a bad line.

What changed recently (as of October 2026)

Three shifts made voice agents practical for ordinary companies. First, speech-to-speech models: OpenAI's Realtime API left beta in August 2025 with the gpt-realtime model, SIP phone calling, remote MCP server support and asynchronous function calling (long tool calls no longer freeze the conversation). Second, voice agent platforms such as Vapi, Retell AI, ElevenLabs Agents and Bland package the whole pipeline (speech recognition, model, voice, telephony, tool calls) behind a dashboard and an API. Third, Indian-language speech got much better: Sarvam AI's current models include Saaras v4 for speech-to-text in 22 Indian languages plus English, and Bulbul v3 for text-to-speech in 10 Indian languages plus English, and the government's Bhashini platform offers language AI services for Indian languages to developers.

Manager's lens

Voice is the most human-facing agent you can build, which makes it the fastest to delight people and the fastest to embarrass you. Start with internal callers (your own salespeople, your own field engineers) before you let a voice agent call or answer customers. Internal users forgive a slow answer; customers hang up and post about it.

When to pick it

Pick voice when the user's hands or eyes are busy (driving, on a shop floor, at a customer site), when the user base prefers calling to typing, or when an existing phone process is high-volume and repetitive: order status, appointment booking, simple policy queries. In India, voice also reaches people who are more comfortable speaking their own language than typing in English.

Don't pick voice for anything that needs the user to compare options visually, read a contract, or approve a long list. And be very careful with outbound calls to customers. Telecom rules on commercial communication, consent and calling hours apply, and an AI voice doesn't exempt you from any of them.

Strengths

  • Works anywhere there's a phone signal, with no app to install.
  • Natural for users who prefer speaking, including in Indian languages.
  • Platforms handle the hard real-time engineering for you.
  • Tools via webhooks reuse the same back-end functions as your chat agents.
  • Every call can produce a transcript and a structured summary.

Watch-outs

  • Latency above a second or so feels awkward; tool calls make it worse.
  • Speech recognition errors on names and numbers ("fifteen" vs "fifty").
  • Per-minute costs stack across several vendors.
  • Recording, consent and telemarketing rules need legal review.
  • Voice cloning and impersonation risks if voices or callers aren't verified.

How it works

There are two architectures. Most production systems in 2026 still use the first; the second is catching up quickly.

Cascaded pipeline. Audio goes to speech-to-text (STT), which streams words. A turn detector decides the caller has finished. The text goes to an LLM, which may call tools and then writes a reply. Text-to-speech (TTS) turns the reply into audio, streamed back as it's generated. Each box is swappable: Sarvam for Hindi STT, your preferred LLM, ElevenLabs for the voice.

Speech-to-speech. One realtime model takes audio in and produces audio out, with tool calling built in. Fewer hops usually means lower latency and better handling of tone and interruptions. The trade-off is less choice of components and less visibility into the intermediate text, though transcripts are still produced.

The latency budget

In conversation, people notice a pause well under two seconds. So voice teams work to a budget for the time between the caller stopping and the agent starting to speak. The ranges below are illustrative design targets, not benchmarks; measure your own stack.

Turn-taking and interruptions

Callers interrupt. "Actually, make that eight percent." A good agent stops talking immediately (barge-in), throws away the rest of its sentence, and listens. Callers also make small noises ("haan", "okay") that aren't interruptions. Platforms expose settings for both; you will tune them on real calls, not in the dashboard.

Numbers deserve special care. Have the agent read back figures that matter ("Ten percent for Sahyadri Hospitals, is that right?") before calling a tool. On a noisy line, "fifteen" and "fifty" are one consonant apart, and in this policy one of them needs the Regional Head.

Build the Deal Desk agent

We'll build "call the sales desk" on Vapi. Retell AI and ElevenLabs Agents follow the same pattern: an assistant with a prompt, a voice and a transcriber, plus custom tools that call your URL. You'll need a Vapi account, a model provider key (or Vapi's included models), and somewhere to run a small Python web server with a public HTTPS URL.

  1. Create the assistant

    In the Vapi dashboard, create an assistant named "Meridian Sales Desk". Choose a model, a transcriber that handles Indian English (and Hindi, if your team code-switches; test a few providers), and a voice. Set the first message: "Meridian sales desk. Which customer and what discount?"

  2. Write a voice-first prompt
    You are Meridian's sales desk on the phone, speaking to Meridian salespeople.
Speak in short sentences. One question at a time. No lists, no symbols.
Say percentages as words ("ten percent").

Process:
1. Get the customer name and the discount. Repeat both back and confirm.
2. Call find_customer, then margin_after_discount.
3. Cap is 3 percent if late payments are 2 or more; otherwise Bronze 5,
   Silver 8, Gold 12. Margin after the discount must be 12 or more.
4. Within both rules: say it's approved within policy and that a confirmation
   text is on its way.
5. Otherwise: explain the rule in one sentence, call request_approval
   (Regional Head above 15 percent, else Sales Manager), and say the caller
   must not confirm anything to the customer yet.
While a tool runs, say "One moment, checking." Never invent numbers.
If the caller asks for anything else, offer to transfer to the sales office.

    What this does: a chat prompt reads badly aloud, so this one bans lists and symbols, forces read-back confirmation of the two numbers, and scripts a short filler line for tool calls. The policy is the same as on every page.

  3. Add three function tools

    In Vapi, create function tools named find_customer, margin_after_discount and request_approval, each with a description and JSON-schema parameters matching the site-wide signatures, and the same server URL, for example https://dealdesk.meridian-internal.example/vapi/tools. Add a Bearer Token credential to the server so Vapi sends Authorization: Bearer <token> with each request. Add Vapi's transfer tool pointing at the sales office number.

  4. Write the webhook server

    Vapi sends a POST whose message.type is tool-calls with a toolCallList. Your server must answer every call with a results array, each item carrying the matching toolCallId and a string result (or error), always with HTTP 200.

    # pip install "fastapi==0.115.*" "uvicorn==0.30.*"
import json, os
from fastapi import FastAPI, Request, HTTPException

app = FastAPI()
TOKEN = os.environ["VAPI_TOOL_TOKEN"]          # same token as the Vapi credential

CUSTOMERS = {
    "sahyadri hospitals": {"id": "C-101", "tier": "Gold", "late": 0, "margin": 22},
    "bluewave logistics": {"id": "C-102", "tier": "Silver", "late": 2, "margin": 18},
    "orchid schools trust": {"id": "C-103", "tier": "Gold", "late": 0, "margin": 25},
    "kite fintech": {"id": "C-104", "tier": "Bronze", "late": 0, "margin": 16},
    "trident engineering": {"id": "C-105", "tier": "Silver", "late": 1, "margin": 20},
}

def find_customer(name: str) -> dict:
    return CUSTOMERS.get(name.strip().lower(), {"error": "not found"})

def margin_after_discount(current_margin_pct: float, discount_pct: float) -> float:
    return float(current_margin_pct) - float(discount_pct)

def request_approval(customer_id: str, discount_pct: float, approver: str, reason: str) -> str:
    # Production: create a ticket and message the approver. A human decides.
    return f"Request for {customer_id} at {discount_pct}% sent to {approver}."

TOOLS = {"find_customer": find_customer,
         "margin_after_discount": margin_after_discount,
         "request_approval": request_approval}

@app.post("/vapi/tools")
async def vapi_tools(request: Request):
    if request.headers.get("authorization") != f"Bearer {TOKEN}":
        raise HTTPException(status_code=401)
    body = await request.json()
    results = []
    for call in body.get("message", {}).get("toolCallList", []):
        name = call["function"]["name"]
        args = call["function"].get("arguments") or {}
        if isinstance(args, str):
            args = json.loads(args)
        try:
            output = TOOLS[name](**args)
            results.append({"toolCallId": call["id"], "result": json.dumps(output)})
        except Exception as exc:
            results.append({"toolCallId": call["id"], "error": f"{name} failed: {exc}"})
    return {"results": results}

    What this does, line by line in plain English. The token check rejects any request that doesn't carry the secret you configured in Vapi, so strangers can't call your tools. CUSTOMERS is demo data; in production these functions query your CRM or database. The three functions are the standard Meridian tools. TOOLS maps the name Vapi sends to the function to run. The endpoint loops over every tool call in the message (there may be more than one), runs it, and returns the result as text with the same toolCallId so Vapi can match answers to questions. Errors come back as text too, so the agent can say "I couldn't find that customer" instead of going silent.

  5. Test with a web call, then attach a number

    Use the dashboard's test call to run the three reference cases out loud, including an interruption. Then attach a phone number. For Indian numbers, teams typically use an Indian telephony provider such as Exotel or Plivo and connect it over SIP; Plivo publishes a Vapi integration guide. Restrict inbound calls to your salespeople's registered numbers.

Tip

Log every call's structured outcome (customer, discount, decision, approver) to the same decisions table your chat agents use. Then voice is just another channel into one process, and the sales head sees one report.

Taking it to production

Identity: who is calling?

Caller ID can be spoofed. For an internal desk, combine an allow-list of registered numbers with a short PIN or a callback to the registered number before discussing margins. Never use voice alone as authentication for anything financial; cloned voices are cheap now.

Consent, recording and telecom rules

Phrase this carefully with your legal team, because the rules depend on who you call and why. Some points that usually come up in India:

  • Recordings and transcripts contain personal data, so the DPDP Act 2023 applies: tell callers the call is recorded and why, keep recordings only as long as needed, and secure them.
  • TRAI's commercial communication regulations (TCCCPR 2018, amended in February 2025) govern promotional and service calls to customers: registered senders, designated number series (140-series for promotional calls, 1600-series being mandated for service and transactional calls from regulated entities such as banks), consent and Do Not Disturb preferences, with penalties up to disconnection and blacklisting. An AI caller is still a caller.
  • It is good practice, and in some jurisdictions a legal requirement (the EU AI Act includes transparency duties for AI that interacts with people), to tell callers they're speaking with an AI.

An internal sales desk that your own staff call is a much simpler compliance case than outbound calls to customers. That's one more reason to start there.

Hosting and data

Your webhook server is the part you control: run it in an Indian cloud region if data residency matters, behind HTTPS, with the token check above and least-privilege access to the CRM. Check where the voice platform processes and stores audio and transcripts, and switch off recording if you don't need it.

Cost control

Voice costs are per minute and stack: platform fee, STT, LLM, TTS and telephony, each billed by a different line item or vendor. Keep calls short by design (the prompt above aims for under a minute), cap maximum call duration, and review the longest calls weekly; they're usually confused callers or loops.

Monitoring and approvals

Track latency per turn, transcription errors on customer names, tool error rates and how often callers ask for a human. Listen to a sample of calls every week; dashboards miss tone. Approvals stay in your approval system, and the caller hears only "requested", never "approved", unless a human has approved.

  • Caller verification beyond caller ID
  • Recording notice and retention period agreed with legal
  • Outbound calling reviewed against TRAI rules before any customer calls
  • AI disclosure in the greeting
  • Webhook server authenticated, in the right region, least privilege
  • Maximum call length and monthly spend caps set
  • Weekly call sampling and latency review
Watch out

Speech recognition tends to struggle with proper nouns: customer names, product codes, Indian place names. Add a confirmation step for every name the tool will look up, and give the transcriber a keyword list (most platforms support this) with your customer names.

Practice and quiz

  1. Rewrite for the ear

    Take the chat version of the Deal Desk answer for Bluewave at 6% ("Decision: ESCALATE. Checks: cap 3%, margin after 12%...") and rewrite it as something an agent would say on a call in under 25 words.

    Hint / model answer

    "Bluewave has two late payments this year, so they're capped at three percent. I've asked the Sales Manager about six. Hold off confirming." (23 words). No symbols, the reason first, the action second, the instruction last.

  2. Plan the latency

    Your test calls show a 2.5-second pause after the caller asks about a discount. The trace shows two sequential tool calls of about 700 ms each. Suggest three changes.

    Hint / model answer

    Combine lookup and margin into one tool (one round trip); have the agent say "One moment, checking" as soon as it calls the tool; move the webhook server closer to the voice platform's region; consider a faster model or a speech-to-speech model. Then measure again.

  3. Compliance memo

    Meridian's marketing head wants the voice agent to call 2,000 hospital purchase managers to offer a festive discount. Write five questions you'd ask legal before saying yes.

    Hint / model answer

    Is this promotional communication under TRAI rules, and are we a registered sender using the designated number series? Do we have recorded consent from these contacts, and have we checked Do Not Disturb preferences? What do we tell people about recording and AI under the DPDP Act? What calling hours apply? How do people opt out, and how fast do we honour it?

What is the main advantage of a speech-to-speech realtime model over a cascaded STT → LLM → TTS pipeline?

  1. It never makes mistakes on numbers
  2. It lets you choose a different vendor for each stage
  3. Fewer hops, which usually means lower latency and more natural turn-taking
  4. It doesn't need tools

Removing hops cuts delay. Mixing vendors per stage (b) is the cascaded pipeline's advantage, not the realtime model's.

Why does the voice prompt make the agent repeat the customer name and discount before calling tools?

  1. Speech recognition can mishear names and numbers, and a wrong figure can change the approver
  2. To make calls longer
  3. Vapi requires it
  4. To train the speech model

"Fifteen" and "fifty" sound alike on a bad line, and above 15% the approver changes to the Regional Head.

In Vapi's tool webhook, how does your server tell Vapi which answer belongs to which tool call?

  1. By returning results in the same order
  2. By returning a different HTTP status code per tool
  3. By including the tool name only
  4. By echoing each call's id as toolCallId in the results array

Vapi matches by toolCallId, and order doesn't matter. Vapi's docs also say to return HTTP 200 even for failures, using an error field.

Which is the safest first deployment for a Meridian voice agent?

  1. Outbound promotional calls to hospital buyers
  2. An internal line that Meridian's own salespeople call
  3. Answering all customer calls with no human transfer
  4. Cloning the CEO's voice for announcements

Internal callers are known, forgiving and outside most telemarketing rules. Outbound promotion triggers TRAI consent and number-series rules.

What should the agent say while a slow tool call is running?

  1. Nothing; silence is professional
  2. A guess at the likely answer
  3. A short filler such as "One moment, checking"
  4. Ask the caller to call back later

Silence makes callers think the line dropped. A brief filler buys time without inventing anything.

Key takeaways

  • A voice agent is an ordinary agent plus speech in and speech out; tools via webhooks are the same functions your chat agents use.
  • Latency and turn-taking make or break the experience; budget for them and add fillers during tool calls.
  • Confirm names and numbers aloud before acting on them.
  • Start with internal callers; outbound calls to customers bring TRAI, DPDP and disclosure obligations.
