Five rules of thumb

  1. Follow the data

    The method that sits closest to the data and the people usually wins. A brilliant agent that can't read the CRM loses to an average one that can.

  2. Prototype cheap, rebuild if it earns it

    Prove the value in a configured assistant or a workflow tool in a week. Only move to code or a platform when the pilot numbers justify it. The design (instructions, tools, tests) carries over; the plumbing doesn't need to.

  3. Start with one agent and a few tools

    Multi-agent setups cost more tokens and are harder to debug. Reach for them when one agent's instructions get too long to follow or the jobs need different permissions.

  4. Put your tools behind MCP

    If you expect more than one agent to need the same systems, build the integration once as an MCP server. It cuts lock-in more than any framework choice.

  5. Choose for the people who will maintain it

    A LangGraph agent with no Python team behind it is a liability by month three. A Copilot Studio agent in a company with a strong Power Platform team can run for years.
